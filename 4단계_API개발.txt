너는 FastAPI, PostgreSQL, SQLAlchemy 기반 검색 API 개발에 능숙한 백엔드 개발자다.

현재 NCS 추천 시스템은 PostgreSQL에 원본 테이블, 검색용 테이블, 임베딩 준비 테이블이 구성되어 있다.

목표:
사용자가 부서명, 직무명, 직무 설명 또는 복합 문장을 입력하면 추천 세분류, 수행직무, NCS 능력단위를 JSON으로 반환하는 FastAPI API를 개발한다.

요청사항:

1. .env 파일에서 PostgreSQL 접속정보를 읽도록 해줘.
2. SQLAlchemy를 사용해 DB 연결을 구성해줘.
3. Swagger에서 테스트 가능하도록 Pydantic schema를 작성해줘.
4. 오류 발생 시 명확한 에러 메시지를 반환해줘.
5. 초보자도 이해할 수 있도록 충분한 주석을 작성해줘.
6. requirements.txt를 작성해줘.
7. README.md에 설치 및 실행 방법을 작성해줘.

API 목록:

GET /api/health

- 서버 상태 확인

POST /api/search/full

- 입력: query, top_k
- 출력: 세분류 추천 + 직무 추천 + 능력단위 추천

POST /api/search/subcategories

- 입력: query, top_k
- 출력: 추천 세분류 Top K

POST /api/search/jobs

- 입력: query, top_k
- 출력: 추천 직무 Top K

POST /api/search/units

- 입력: query, top_k
- 출력: 추천 능력단위 Top K

GET /api/subcategories/{subcategory_code}/units

- 입력: subcategory_code
- 출력: 해당 세분류에 포함된 능력단위 체크리스트

요청 예시:

{
  "query": "품질팀에서 불량 원인을 분석하고 개선대책을 수립한다",
  "top_k": 10
}

서비스 구조:

1. 검색 로직 → services/search_service.py
2. 정규화 로직 → services/normalize_service.py
3. 동의어 탐지 → services/dictionary_service.py
4. 검색 로그 저장 → services/log_service.py
5. 향후 vector 검색 확장 → services/vector_service.py

추가 조건:

1. 현재 단계에서는 실제 pgvector 검색은 구현하지 않는다.
2. vector_search 함수 구조만 작성한다.
3. 향후 embedding API 연결 가능하도록 함수 구조를 분리한다.
4. keyword_score, vector_score, final_score 구조를 유지한다.
5. PostgreSQL Full Text Search는 plainto_tsquery 또는 websearch_to_tsquery 기반으로 구현한다.
